Introduction

This artifact adapts my Activity 2.3 comparison of spam detection and language translation for team leaders and engineering managers evaluating AI projects. Deep learning is a subset of machine learning, using neural networks with multiple hidden layers. The comparison therefore distinguishes a conventional feature-based approach from a deep neural approach, rather than treating them as separate fields. [1], [5]

Description

The work sample is a practical comparison brief built around two examples from my coursework: a basic email spam classifier and contextual language translation. It includes a decision table, application-specific reasoning and references. The downloadable Word guide provides the tangible deliverable. This is a conceptual analysis; no model was trained, dataset tested or performance benchmark measured.

Example 1: A basic email spam classifier

A basic spam filter can turn an email into measurable signals, such as keyword indicators and link counts, then use logistic regression to estimate the probability that it is spam. A chosen threshold converts that probability into a label. Google's teaching material explicitly uses spam detection as a logistic-regression use case. [2]

This is a reasonable baseline to investigate when the signals are useful and the team needs a model whose feature weights can be inspected. It is not a claim that this approach is sufficient for Gmail: Google documented an LLM trained on phishing, malware and spam in 2024. Whether a simpler classifier meets a real project's needs must be tested. [4]

Example 2: Contextual language translation

Translating a sentence requires modeling relationships across its words. In the original coursework, the word "bank" illustrates why surrounding text matters: a financial institution and a river bank need different interpretations. This is an explanatory example, not an observed translation result.

Neural translation can learn contextual representations from data. Google's 2020 technical account described a Transformer encoder paired with an RNN decoder, and emphasized training-data quality and translation evaluation. That historical example explains the suitability of a neural approach; it does not establish the exact architecture used by Google Translate today. [3]

How to use the comparison

Start with the task and an evaluation plan. Compare a practical baseline with an alternative on representative data, including the cost of mistakes and human review. Reusing a pretrained model changes the work involved, so assess the proposed system rather than assuming every deep-learning project requires training from scratch. These are proposed decision criteria, not results measured in this coursework.

Objective

Explain why different problems can justify different modeling approaches, and help a reader ask useful questions about input representation, context, resources and evaluation before selecting a method.

Value Proposition

Unique Value

This artifact connects two familiar applications to explicit model-selection questions. The source-backed distinction between an illustrative spam classifier and a production service makes the comparison more precise.
